This log records implemented redesign behavior with source evidence. [`design.md`](../../design.md) remains the visual north star, and the existing application remains authoritative for product behavior and backend contracts.

## Implemented behavior

| Decision | Source evidence | Boundary |
| --- | --- | --- |
| Use a light game-dashboard system with an Inter type family, blue-gray canvas, white surfaces, navy text, cool-blue primary actions, semantic state colors, calibrated radii, and rare soft shadows. | `frontend/src/index.css`; `frontend/src/components/ui/button.tsx`; `input.tsx`; `card.tsx`; `badge.tsx`; `tabs.tsx`; `switch.tsx`; `select.tsx`; `dropdown-menu.tsx`. | Semantic tokens style existing frontend flows only. `font-display` intentionally aliases Inter. |
| Use a responsive icon-led shell for authenticated setup routes and remove all app chrome from active gameplay. | `frontend/src/components/layout/PageShell.tsx`; `AppSidebar.tsx`; `MobileBottomNav.tsx`; `app-navigation.ts`; `frontend/src/components/AppHeader.tsx`. | Navigation exposes only Home, Create, Join, and the account action. Direct create and join retain the shell; `/game/:gameId` does not. |
| Keep landing and authentication on the shared visual system without authenticated app chrome. | `frontend/src/pages/Landing.tsx`; `Login.tsx`; `SignUp.tsx`; `frontend/src/components/landing/LandingNav.tsx`; `Hero.tsx`; `Features.tsx`; `HowItWorks.tsx`; `Coverage.tsx`; `FinalCta.tsx`; `frontend/src/components/AuthLayout.tsx`; `frontend/src/clerk/appearance.ts`. | Landing actions use existing routes and anchors. Clerk continues to own password, Google SSO, MFA, and verification branches. |
| Make Join and Host/Create the dashboard hierarchy, followed by the real public-room feed. | `frontend/src/pages/Dashboard.tsx`; `frontend/src/components/dashboard/DashboardHero.tsx`; `LiveRoomsSection.tsx`; `PublicRoomsList.tsx`; `LiveRoomCard.tsx`. | Public cards render only existing room-code, host, capacity, round, and generation fields. Full rooms disable Join. |
| Preserve the existing file-or-saved-quiz creation contract and direct room-code join contract in responsive page layouts. | `frontend/src/pages/CreateGame.tsx`; `JoinGame.tsx`; `frontend/src/components/forms/RoomCodeInput.tsx`; `frontend/src/components/quiz-rooms/QuizPickerList.tsx`; `RoomSettings.tsx`; `UploadPanel.tsx`; `RoomPreviewCard.tsx`; `JoinRoomPanel.tsx`; `HowJoiningWorks.tsx`; `frontend/src/components/lobby/QuizGenerationPanel.tsx`. | No topic/manual authoring or retained-file promise was added. API calls, payloads, validation, retry, paste, and Enter behavior remain existing contracts. |
| Keep lobby membership, readiness, host start, room-code sharing, and generation state socket-driven. | `frontend/src/pages/Lobby.tsx`; `frontend/src/components/lobby/PlayerCard.tsx`; `QuizGenerationPanel.tsx`; `frontend/src/hooks/useLobbySocket.ts`; `frontend/src/stores/lobbyStore.ts`. | Player cards present store data and reduced-motion-aware arrival only. Host requirements and socket events are unchanged. |
| Keep live game interaction phase-driven with clear countdown, timer, answer lock, feedback, leaderboard, results, and connection states. | `frontend/src/pages/Game.tsx`; `frontend/src/components/game/Countdown.tsx`; `Timer.tsx`; `QuestionCard.tsx`; `AnswerFeedback.tsx`; `RoundResults.tsx`; `Leaderboard.tsx`; `GameResults.tsx`; `ConnectionBanner.tsx`; `frontend/src/hooks/useGameSocket.ts`; `frontend/src/stores/gameStore.ts`. | Correctness, timing, score, and rank stay server/store authoritative. Presentation does not expose answers early or invent unsupported replay, review, share, accuracy, or analytics actions. |
| Treat room codes as a first-class game artifact. | `frontend/src/components/forms/room-code-utils.ts`; `RoomCodeInput.tsx`; `frontend/src/pages/Lobby.tsx`; `frontend/src/components/dashboard/LiveRoomCard.tsx`. | Preserve six uppercase alphanumerics, paste and Enter flows, explicit labels/errors, monospaced type, and distance readability. |
| Preserve accessible control semantics and state communication across the redesign. | `frontend/src/components/ui/`; `frontend/src/components/AccountMenu.tsx`; `frontend/src/components/layout/`; `frontend/src/components/game/`; `frontend/src/components/quiz-rooms/`. | Interactive targets retain accessible names, visible focus, disabled/invalid states, reduced-motion fallbacks, and text/icon cues alongside semantic color. Rendered/manual verification remains pending. |
| Redesign by buildable vertical slices and defer unsupported controls and product features. | Implemented source is organized across shared foundation, shell, landing/auth, dashboard, create/join, lobby, and game components; unsupported inventory remains recorded in `docs/design/COMPONENTS.md`. | Search, notifications, categories/covers, quiz detail actions, manual/topic authoring, solo practice, result sharing, quiz editing, and host analytics still require separate contracts. |

| Scoped Fluent dark home tokens | `frontend/src/index.css` — added `[data-theme="fluent-dark"]` semantic tokens scoped to HomeWorkspace; CSS variables selected to approximate Fluent 2 dark neutrals and communication blue with WCAG AA body contrast. | Tokens are scoped to elements using `data-theme="fluent-dark"` so the light app chrome and non-home routes remain unchanged; this is a foundation for gradual migration. |
