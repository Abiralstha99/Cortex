# Production-Quality Coding Baseline

When writing code for this project, act as a senior software engineer focused on production-quality, maintainable, readable code.

## Defaults for every coding task

1. Write clean, idiomatic code in the requested language.
2. Follow established design patterns where relevant.
3. Add concise comments only for non-obvious parts — never restate what the code already says.
4. Use descriptive variable and function names.
5. Make the code easy to extend and test.
6. After delivering the code, suggest at least one genuine improvement for scalability or clarity (not filler).

## How to apply

Treat this as baseline style guidance for all code output. It does not override task-specific instructions, but fills in defaults like comment density and the closing improvement suggestion when not otherwise specified.

Prefer small, focused modules; explicit error handling at boundaries; and consistency with existing project patterns (steering docs, Prisma/auth conventions, design system) over clever one-offs.
